## Exercise 1

**Goal:** write a macro that handles conditional logic, not just a one-line substitution.

### Step 1 - Find the pattern

- [ ] Step complete

`fct_ad_impressions.sql` computes `click_through_rate` with a `case` expression that guards against dividing by zero when `impressions_count` is `0`. This is a "safe division" pattern - useful anywhere you divide two columns and can't guarantee the denominator is non-zero.

### Step 2 - Write `safe_divide`

- [ ] Step complete

Write a macro, `safe_divide(numerator, denominator, precision=4)`, that returns `0` when the denominator is zero and otherwise returns the rounded division - matching what `fct_ad_impressions.sql` already does inline, but reusable. Give `precision` a default value so most callers don't need to pass it.

??? tip "Hint: default argument values in Jinja macros"
      See [Jinja and macros](https://docs.getdbt.com/docs/build/jinja-macros) for how macro arguments and default values are declared.

### Step 3 - Apply it

- [ ] Step complete

Edit `fct_ad_impressions.sql` to call your new macro instead of the inline `case` expression, and confirm the model still builds and the column's values are unchanged.

**Deliverable:** the `safe_divide` macro and the updated `fct_ad_impressions.sql`.

## Extension

You now have near-identical dev/prod schema-naming logic living in two separate macros, one per project, with no relationship between them.

### Step 1 - Decide: duplicate or share?

- [ ] Step complete

dbt Mesh's `dependencies.yml` only resolves `ref()`/`source()` for public models across a project boundary - it doesn't share macros. The only way to genuinely share macro code between `mediapulse_base` and `mediapulse_analytics` is an installable package both projects depend on via `packages.yml`. Decide, and justify in writing: is it worth extracting this logic into a small internal package, or is keeping two independently-maintained copies the more sensible call for a macro this small?

??? tip "Hint: packages and macro dispatch"
      [Jinja and macros](https://docs.getdbt.com/docs/build/jinja-macros) and the [dispatch](https://docs.getdbt.com/reference/dbt-jinja-functions/dispatch) reference cover how package-based macro sharing and dispatch actually work - useful context before you argue either side.
